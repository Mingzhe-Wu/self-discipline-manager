# Built-in task categories

Category is Task-level metadata: a stable key stored once on tasks, never on occurrences. Shared definitions in shared/taskCategories.ts map study/work/exercise/personal/chores/meal/rest/entertainment/other to readable labels and emoji. Other is the default for omitted creation input and legacy tasks. Invalid supplied keys are rejected by the service; updates that omit category retain the existing value. The UI tolerates unknown display values by showing Other.

The existing create/update/occurrence-plan DTOs carry category through the existing validated IPC/preload API. No new channels, raw IPC access or repository shortcuts were added. The repository's typed inserts/selects already propagate the Drizzle field. Recurrence projection looks up the parent Task, so changing timing retains category. A Sync OFF edit inherits the parent's category when omitted and honors an explicitly selected valid category. Occurrences/history do not duplicate category or snapshot old labels; later category edits change the Task's current classification.

Migration0007_task_categories.sql performs only ALTER TABLE tasks ADD category text DEFAULT 'other' NOT NULL. Its generated Drizzle snapshot and journal entry are committed with the SQL. It does not rewrite titles, planned/actual timestamps, recurrence, exclusions or notification state. Normal runtime migration transaction/journal handling makes the operation atomic and restart safe.

Add/Edit share a nine-option Category selector (emoji + label). Details shows Category. Cards reserve a nonshrinking emoji before the truncated title, prioritizing the emoji when width is scarce; full title and category description remain available through accessible text/title and details. Centered hover retains the same category/title and existing lifecycle action/details button. Category creates no CSS color variants: gray/blue/green continue to mean lifecycle only.

Verification: TypeScript, ESLint, full automated suite and production build; tests/categories.cjs covers stable metadata, validation, persistence/editing, independent recurrence inheritance, reopen, legacy migration and server-rendered components. Run node tests/windows-categories.cjs after npm run build for isolated rendered verification (or supply an unpacked executable path). The Browser plugin is unavailable, so Playwright Electron drives these checks.

Before using any live profile, migration was tested against an online SQLite backup opened from the real profile in read-only mode. The snapshot held seven prior migrations, 11 tasks, 67 occurrences, 17 reminder-slot rows, one recurrence exclusion and one planning-settings row. Every existing field/row was compared unchanged; each Task gained only category=other. Integrity/foreign-key checks and reopen passed. Evidence is under ignored release/verification/category-real-copy-KGaZ2w/result.json. The live database was not migrated or reset. No NSIS rebuild was performed.
