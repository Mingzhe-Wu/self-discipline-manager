# Timetable overlap layout

## Current policy

All intersecting display intervals form transitive layout groups, including partial overlap, containment and intersections introduced by the 15-minute minimum rendered height. End-to-start touching alone does not group. Cards are processed by visual start time, with original display boundaries and stable task/occurrence IDs as tie-breakers. The first available column whose previous card has ended is reused; default layers keep their existing stable order.

Each group uses width = 1.05 / peak simultaneous column count; two concurrent columns are 52.5% wide, three 35%, five 21%. Count is not the number of tasks in a connected group. One all-day task with ten sequential, mutually non-overlapping short tasks therefore needs only two columns: the short tasks all reuse the second column. Touching endpoints release their column, subject to the existing 15-minute visual floor. Left offsets distribute these columns across the available day width, retaining the existing slight overlap and an exposed selectable strip for concurrent cards. Single cards use full width. Later starts and strict contained cards retain higher default layers. Input data and ordering are never changed.

Hover or keyboard focus temporarily expands a card to full usable width above siblings, anchored at the original top and growing downward, or anchored at the original bottom and growing upward if the visible lower boundary cannot fit it. Mouse leave restores deterministic offsets, widths and stacking. Compact cards retain category emoji and shortened title. Expansion is one continuous lifecycle-colored capsule with two independent regions: a fixed 60px information area opens details, and the full remaining lower area advances lifecycle. A full-width separator divides them; a small details icon is a visual hint only, and no separate action pill remains.

Card top follows its display range: planned start/end before starting, actual start/current execution while running, and actual start/end when finished. Display height is max(display duration, 15 minutes) multiplied by the current timeline density. Five- and ten-minute tasks therefore have a fifteen-minute visual height, while their saved start/end and displayed time labels remain unchanged. The stored planned timestamps are never overwritten by display layout. Expansion remains transient and leaves the underlying display geometry unchanged.

Only the expanded lower region is the lifecycle target: Planned → In Progress → Finished → reset confirmation. Its centered labels are ▶ Press to start, ■ Press to finish and ↺ Press to reset. The upper region only opens details; both native controls stop click propagation. Reset clears actual times only after confirmation. Each hovered region alone gets a muted darkened background, weak inset shadow and local left accent; the surrounding card does not acquire a hover accent. The information region contains title/category/state/planned range with space reserved for its noninteractive details indicator. Short-card hover exposes the full controls without changing task data.

Current verification: 114 automated tests, TypeScript, ESLint and production build passed. Tests cover deterministic overlap groups, exposed staggered columns, the short-card visual floor and immutable planned geometry. An isolated Playwright Electron check verified rendered width/height, hover expansion, 28px details, centered sync checkbox and past one-time creation rejection. QA profiles and screenshots remain under ignored release/verification; no real user database or installer rebuild is required.

Current UI follow-up: viewport density targets eight hours (480 minutes) while keeping proportional positions and scrollable remaining time. The 100ms whole-capsule expansion remains, and lifecycle actions stay locked until animation completion; Ctrl collapses/blocks both regions. Focused verification ran 10 card/viewport tests, regional Electron interaction checks, changed-file ESLint and TypeScript/production build; no packaging or migration QA was run for this follow-up.

Main-card hover expansion keeps the original top and grows downward by default. If the expanded capsule would cross the visible scrollport/day bottom, it keeps the original bottom and grows upward instead. The scale animation uses the same top/bottom anchor; saved timing and default overlap geometry remain unchanged.

Column-reuse regression tests cover an all-day task plus ten separated short tasks, chained overlaps with only two simultaneous cards, a three-way peak followed by reused columns, input permutation stability and unchanged timing data. Both WeekSchedule and MiniDayTimetable use the same layout helper.

After column reuse, each card spans consecutive free columns to its right. A column is free only when none of its base cards intersects any part of this card’s visual interval, including the short-card height floor. Expansion stops at the first occupied column. This fills gaps left by a brief busy period elsewhere in the group while preserving clickable strips for simultaneous cards. Hover animation derives its horizontal origin from the final offset/width so wider cards still animate from their actual resting position.
